# Backlog

The backlog lives in GitHub issues, not in this file:
https://github.com/reactome/reactome-status/issues

Labels: `feature` (new user-facing capability), `coverage` (monitor more, or better), `operations`,
`security` (permission model changes that are already documented in the specs), `small`.
Hardening gaps are tracked privately, not as public issues (constitution, Public repository). The next specified feature is multi-host monitoring
(`specs/001-multi-host-monitoring/`, tracked in issue #17). Anything that alters what is uploaded,
who may upload, or how availability is computed needs a spec before implementation; see the
constitution's Development Workflow.
